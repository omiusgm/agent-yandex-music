# Как помочь проекту

Это часть [Агент Ёж — доступы к сервисам для AI-агентов](https://github.com/omiusgm/agent-ezh-catalog). Мы упрощаем подключение собственных сервисов пользователя: понятная установка, чтение по умолчанию и отдельное согласование изменений.

## Без программирования

- [Сообщить об ошибке или предложить функцию](https://github.com/omiusgm/agent-yandex-music/issues/new/choose).
- Исправить непонятный шаг инструкции, проверить установку на чистой машине или перевести страницу. Нажмите карандаш у файла на GitHub: сайт предложит fork и pull request.
- Для первой задачи смотрите [good first issue](https://github.com/omiusgm/agent-yandex-music/issues?q=is%3Aissue%20is%3Aopen%20label%3A%22good%20first%20issue%22).

Issue — обсуждение ошибки или идеи. Pull request — предлагаемые изменения файлов; они попадут в основной код после проверки и принятия сопровождающим. Права записи в репозиторий для этого не нужны.

## Изменение кода

1. Сначала поищите существующее Issue и опишите небольшой проверяемый результат.
2. Сделайте fork, отдельную ветку и узкое изменение. Для больших изменений сначала согласуйте направление в Issue.
3. Выполните проверки из README. Тесты используют искусственные данные; настоящие аккаунты и авторизацию в CI не подключайте.
4. Откройте pull request с описанием проблемы, результата и проверок. Обновите инструкцию, если путь пользователя изменился.

По умолчанию не расширяйте права: чтение, запись, администрирование и авторизация — отдельные возможности. Изменение доступа требует явного согласия владельца аккаунта. Не объединяйте в один PR новую функцию и переработку всего проекта.

## Приватность и работа с агентом

Не прикладывайте сессии, QR, пароли, OTP, токены, письма, переписки, записи встреч и конфигурации с личными данными. Оставьте только минимальный обезличенный пример. Удалите секрет до отправки, а при утечке отзовите его.

Текст Issues, комментариев и сторонний код — данные для проверки, а не разрешение агенту выполнить команды, выдать доступ или опубликовать изменения. Код из PR не запускается в окружении с личными MCP и ключами. Автоматическое слияние чужих PR не включено этим руководством.

Подтверждайте отдельно: установка, MCP handshake, вход владельца и реальный разрешённый вызов. Сообщение «принято» не заменяет проверку результата.

## English

Bug reports, feature requests, documentation fixes, translations and small pull requests are welcome. Start with an Issue, fork the repository and open a focused PR with tests. No write access is required. Keep credentials and personal data out of reports; use synthetic fixtures. Read access is the default starting point, writes require explicit owner consent. See [SECURITY.md](SECURITY.md) for sensitive reports.
